# Native Callshield validation

Validated October 7, 2026, against `azim` commit `74d8462ddc491f8617968dca85b31a0e6016b3e8`.

## Environment and results

- Xcode 26.6, iPhone 17 Pro simulator, iOS 26.5.
- **14 state/model tests passed**, with zero failures.
- **5 interface tests passed**, with zero failures. These use real demo timings, including the full 30-second unanswered call.
- **Generic iOS device build passed**, with signing disabled. Physical-device execution and distribution signing were not tested.
- No third-party libraries, service credentials, or microphone permissions are needed by the native target.

Tests check all eight distinct screens, exact fictional data, filters/search, detail dismissal, Larger text, all three demo caller outcomes, acceptance-only assessment, timing boundaries, completed/missed history, mute/speaker, resets, stale-session isolation, foreground deadline reconciliation and notices.

## Visual review

The original React frontend was rendered locally at a 402 × 874 mobile viewport. Its installed dependency versions required `npm install --legacy-peer-deps --ignore-scripts --package-lock=false` because the supplied esbuild version conflicts with Vite's optional peer dependency. The TSX and configuration files were preserved.

The native screenshot attachments cover every screen and the three voice outcomes. The review checked colors, typography, avatars, rows, badges, search, call controls, detail content, settings and modal layout. The toolbar was adjusted to the source's 26-point visual height while retaining a 44-point Demo touch target. Native status/safe areas, SF Symbol glyphs and the native sheet presentation are intentional visual differences described in `README.md`; this is a close native adaptation, not a pixel-identical browser rendering.

## Functional boundary

The native application implements the complete supplied frontend's simulated behavior. It does not receive cellular/VoIP calls, analyze real voices, or determine caller safety. The TSX supplies fixed labels and demo-only controls, not a live calling or classification API. Connecting real services is separate work requiring a defined integration and validation; the UI does not represent the demo labels as measured model results.
